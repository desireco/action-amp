# Link Garden spike — comparison report

> One standalone Typebase backend, two peer frontends (Svelte 5, Imba),
> all local. Evidence: `spikes/link-garden/` + the three notes files +
> Playwright browser verification. 2026-09-01.

## 1. Multi-client reality

One backend served both clients with **zero backend changes for the second
client** — but only via a **dev proxy**. Direct cross-origin browser auth is
broken in the bundle: better-auth 404s CORS preflights and 415s non-JSON
content types (verified with curl + browser), regardless of
`trustedOrigins`/`BETTER_AUTH_URL`. With vite proxying `/api` + `/rpc`,
everything is same-origin and works. Cookies are host-scoped (port-agnostic),
so the two clients even shared one session on localhost.

## 2. The Imba delta (the headline measurement)

What Svelte got free (generated typed client, zod-derived types end-to-end,
svelte-check 0 errors) cost Imba **62 hand-rolled lines** (`api.imba`) plus
runtime-only endpoint knowledge — the api-notes HTTP table was the entire
contract, with drift discovered at runtime, not compile time. A shared
OpenAPI/JSON-Schema export would close most of the gap; not attempted
(timebox). The bigger cost wasn't the fetch layer — it was **~1.5h+ of
compiler archaeology** (six distinct traps, all documented in
`imba-cheatsheet.md`), ending in a reproducible renderer bug.

## 3. Head-to-head

| | Svelte 5 | Imba (alpha-vite fork) |
|---|---|---|
| Feature-complete in browser | **yes — verified end-to-end** | partial: auth, boot, data, header render; tabs/list silently dropped |
| Client code | 47-line api + runes UI | 62-line api + UI |
| Bundle | ~148 kB JS | 126 kB JS |
| Toolchain fights | npm crash (→ bun), oRPC url-base gotcha | 6+ (see cheatsheet), renderer bug unresolved |
| Type safety | full, compile-time | none, runtime only |

Honest preference: **Svelte, decisively** — every construct behaved as
documented; Imba's mutation ergonomics are genuinely nicer, but not at
alpha-toolchain cost.

## 4. better-auth greenfield taste

Works, but: no `BETTER_AUTH_URL` → broken CORS behavior; preflight handling
absent in this bundle; sensible session cookie (HttpOnly, SameSite=Lax,
7-day). Fine for greenfield, but it would fight a Wasp-brige migration —
irrelevant for the spike, decisive-adjacent for the real switch.

## 5. Standalone operation

**Yes, naturally**: the backend is its own Bun service (generated by
`typebase-io-cli generate-server`, `bun run start` regenerates + boots).
Learnings: codegen **statically extracts auth config** (dynamic values
silently dropped); `npm start`-style regen-on-every-boot is slow but
self-healing. The `apps/api` shape the switch plan wants is directly
supported.

## 6. Verdict inputs + escape-hatch score

- Typebase: DX genuinely good (typed client, zod-through, Drizzle schema
  iteration), but 0.1.x rough edges are real (CORS/auth bundle gaps, static
  config extraction). As an `apps/api` behind a proxy: workable today.
- **Escape-hatch realism (Svelte → Imba today): 1/5.** The language is
  promising; the vite-plugin + alpha-fork pairing is not production-viable
  (renderer silently drops subtrees, zero errors). Revisit after Imba 2
  final. Gleam/Lustre would face the same non-TS-contract cost measured in
  §2 — the `packages/contract` boundary plus an OpenAPI export is the
  mitigation that actually matters.
- Recommendation: proceed with **Svelte + Typebase-with-proxy** for the
  switch program (or Hono if F7's gates bite); keep Imba on the radar,
  not in the stack.
