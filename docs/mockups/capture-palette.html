Decisions encoded in this prototype

  • Enter commits and closes. The single capture is the common case — one thing on your mind, then back to work. ⌘Enter captures + clears the input + prepends a "✓ captured" row; the palette stays open to add another (rapid-fire). Esc closes without saving. (Reversed 2026-06-30 — previously Enter kept open and ⌘Enter closed.)
  • Shift+Enter = expand. The card grows in place into the vertical property list already shipped in triage-coauthor.html. Same DNA — capture and triage are the same surface at different commitment levels.
  • The capture field grows, never scrolls sideways. One line → wraps → grows to ~4 lines → scrolls internally. Same element on mobile and desktop. Locked 2026-06-22.
  • First-class properties: # (project/goal) and @ (context). Choosing where this goes beats choosing how urgent it is — urgency is triage's job. Priority (!) and size (~) stay parseable but live in the expanded editor.
  • Chips are editable, not decorative. A mis-parsed "tomorrow" gets a hover-X and click-to-edit. Carries the triage "co-author the spec" decision upstream into capture.
  • Confirm summary reads back the commitment in plain English ("Capture as Task · Tomorrow · M · General") — same voice rule as triage, no metadata-chip soup.
  • Mode indicator — CAPTURE — bottom-left, VIM-style. Honors INTERACTION.md §3 even though it's unbuilt in the app today.
  • Mobile = FAB + bottom sheet, not a centered modal. Pull-down-from-top is an alternative gesture (shown faded). Honors the iOS-standard convention from INTERACTION.md.
  • Defaults never auto-Today. When=Someday, Size=M, Priority=Normal, Project=General — the inbox is a staging area, not a commitment. Triage is where Today gets decided.
