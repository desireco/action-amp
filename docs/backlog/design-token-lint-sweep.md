# Design-token lint sweep — the calibrated remainder

`scripts/check-design-tokens.sh` (wired into `npm run lint` in 1ce2382, which
planned this sweep) fails on main with raw colors, font-sizes and radii in
`web/src`. On 2026-09-26 the **lossless** subset landed (exact token equals —
same computed value, zero visual change): all `border-radius` 4/6/8/12/999px/50%
swaps, `font-size` 1rem/0.9rem/1.1rem, the dead `--aa-rose` fallbacks, and a
comment that tripped the color regex. 93 → 55 violations.

What remains **cannot** be bulk-swept mechanically, for three recorded reasons:

1. **The type scale was calibrated to collapse, not to match.** tokens.css:
   "The buckets collapse ~290 ad-hoc font-size declarations to seven named
   steps. Migrate components as you touch them; **do not bulk-rewrite**."
   Mapping 0.95rem → base or md, 17px → lg, 36px → 2xl etc. changes rendered
   size slightly — a deliberate visual change that belongs to
   `docs/DESIGN-SYSTEM.md`, not a lint fix.
2. **The off-scale radii have no token.** `0` (square, share page ×2 and the
   partially-tokenized settings sheet `0 0 var(--aa-radius-md)`), `2px`
   (CommandPalette kbd), `7px` (RowEditor), `10px` (task page ×2) — either new
   tokens get defined (a design-system decision) or the values snap to
   neighbors with a visual delta.
3. **Five raw colors need tokens that don't exist yet** (see below): a
   constant light-on-color (`#fff` ×2 in Overlays, the undefined
   `--aa-primary-contrast` fallback in app-shell), a white-alpha tint
   (app-shell 0.18), and the `<meta name="theme-color">` brand literal, which
   cannot reference a CSS var at all (gate limitation — needs a gate
   whitelist or a build-time injection).

## Suggested path to green

1. DESIGN-SYSTEM decision (one session): confirm the bucket for each ad-hoc
   size above (they cluster: onboarding/public hero sizes 27–44px suggest a
   `--aa-text-display` step may be wanted; 8–10px micro-labels suggest an
   `--aa-text-2xs`), and whether `--aa-radius-none: 0` should exist.
2. Then sweep by hand per surface (public → onboarding → founding100 →
   in-app), screenshotting each surface once — the collapse is lossy by
   design, so each surface gets one visual pass.
3. Until then `npm run lint` stays red on main; treat the gate as
   advisory-not-blocking for CI (it already is — nothing gates on it).
